# ADC and PWM: Analog at the Edges

Digital processors live in a world of 0s and 1s, but the physical world is relentlessly analog — temperatures, pressures, audio signals, motor speeds. The ADC (Analog-to-Digital Converter) and PWM (Pulse-Width Modulation) peripheral are the two most common bridges between these worlds.

## ADC: Analog to Digital

An ADC samples a continuous voltage and maps it to an integer code. The two defining parameters are:

| Parameter | Meaning |
|---|---|
| **Resolution** | Number of output bits (8, 10, 12, 16 …) |
| **Full-scale range** | Voltage range (e.g., 0 V to 3.3 V) |

The conversion formula is:

```
digital_code = round( V_in / V_ref × (2^N − 1) )
```

For a 12-bit ADC with `V_ref = 3.3 V` and `V_in = 1.65 V`:

```
code = round(1.65 / 3.3 × 4095) = round(2047.5) = 2048
```

To recover voltage from a code:

```
V_in = code × V_ref / (2^N − 1)
```

### ADC Key Registers

| Register | Purpose |
|---|---|
| `CR1` / `CR2` | Enable, start conversion, continuous vs. single mode |
| `SMPR` | Sample time — longer = more accurate on high-impedance sources |
| `SQR` | Sequence register — which channels to scan and in what order |
| `DR` | Data register — read the latest conversion result |
| `SR` | Status: EOC (end of conversion), OVR (overrun) |

### ADC Conversion in Firmware

```c
// Start a single conversion on channel 3
ADC1->SQR3  = 3;               // channel 3 first in sequence
ADC1->CR2  |= ADC_CR2_SWSTART; // software-start

// Wait for end of conversion
while (!(ADC1->SR & ADC_SR_EOC));

uint16_t raw = ADC1->DR;       // reading DR clears EOC
float voltage = raw * 3.3f / 4095.0f;
```

### Oversampling

To increase effective resolution beyond hardware bits, firmware reads multiple samples and averages them. Oversampling by 4N increases resolution by 1 bit. Many modern ADCs do this in hardware, but it can also be done in software at the cost of sample rate.

## PWM: Digital to Analog (Sort Of)

PWM is not a true DAC — it does not output an arbitrary voltage. Instead it outputs a square wave whose **duty cycle** encodes an "average" value. The load (motor, LED, heater) integrates the signal due to its own inertia or an explicit RC filter.

```
Duty cycle = t_on / T_period × 100%

Average voltage = Duty cycle × V_supply
```

For a 50% duty cycle at 3.3 V: average = 1.65 V.

### PWM Hardware

PWM is generated by a **hardware timer** with a compare register:

```
Period T:   |<------------->|
Counter:    0 ___/\/\/___  ARR (auto-reload register)
Output:      HIGH until CCR, then LOW

Duty = CCR / ARR
```

### PWM Configuration in Firmware

```c
// 1 kHz PWM, 50% duty cycle, assuming timer clock = 72 MHz
TIM3->PSC = 71;           // prescaler: 72 MHz / 72 = 1 MHz timer clock
TIM3->ARR = 999;          // period: 1 MHz / 1000 = 1 kHz
TIM3->CCR1 = 499;         // compare: duty = 499/999 ≈ 50%
TIM3->CCMR1 = (6 << 4);  // PWM mode 1
TIM3->CCER |= TIM_CCER_CC1E; // enable channel 1 output
TIM3->CR1  |= TIM_CR1_CEN;   // start timer
```

### SystemC PWM Model

```cpp
SC_MODULE(PWMModel) {
    sc_out<bool> pwm_out;

    uint32_t arr = 999;   // auto-reload
    uint32_t ccr = 499;   // compare value
    uint32_t psc = 71;    // prescaler

    void pwm_thread() {
        double timer_clk_ns = (psc + 1) / 72.0 * 1000.0; // ns per tick
        while (true) {
            pwm_out.write(true);
            wait(ccr * timer_clk_ns, SC_NS);
            pwm_out.write(false);
            wait((arr - ccr) * timer_clk_ns, SC_NS);
        }
    }

    SC_CTOR(PWMModel) {
        SC_THREAD(pwm_thread);
    }
};
```

## ADC vs. PWM: The Dual Role

A useful mental model:

| Peripheral | Direction | Domain |
|---|---|---|
| ADC | Analog → Digital | Input (sensors, potentiometers) |
| PWM | Digital → Analog | Output (motors, LEDs, speakers) |

Together they form the complete analog interface of an embedded system.

## Common Pitfalls

- **ADC input impedance** — high-impedance sources need a long sample time (`SMPR`) or a buffer op-amp, or the sampled value will be too low.
- **ADC overrun** — starting a new conversion before reading `DR` loses the previous result. Use DMA in continuous mode.
- **PWM frequency too low** — visible LED flicker below ~100 Hz; audible motor whine below 20 kHz.
- **PWM glitches on CCR update** — updating the compare register mid-period can cause a runt pulse. Load `CCR` only when the timer is at zero, or use shadow/preload registers.

> **Interview answer:** An ADC maps voltage to a digital code: `code = V_in / V_ref × (2^N − 1)`. A PWM generates a square wave whose duty cycle encodes the desired analog level as an average. Both are configured via hardware timers; key pitfalls are ADC overrun and PWM glitches from mid-period compare-register updates.

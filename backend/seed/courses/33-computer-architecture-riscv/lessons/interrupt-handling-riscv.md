# Interrupt Handling in RISC-V

Interrupt handling in RISC-V involves three cooperating layers: the CSR-level enable/pending bits defined by the ISA, the Core-Local Interrupt Controller (CLINT) for timer and software interrupts, and the Platform-Level Interrupt Controller (PLIC) for all external device interrupts. Understanding all three layers is necessary to write a complete interrupt handler.

## Interrupt Enable Hierarchy

An interrupt fires only when three conditions are all true simultaneously:

1. **Global enable** — `mstatus.MIE = 1` (machine interrupts globally enabled).
2. **Per-source enable** — the corresponding bit in `mie` (Machine Interrupt Enable) is set.
3. **Pending** — the corresponding bit in `mip` (Machine Interrupt Pending) is set.

```
mstatus.MIE  AND  mie.MTIE  AND  mip.MTIP  → machine timer interrupt fires
```

The `mie` and `mip` registers are parallel bit arrays:

| Bit | `mie` field | `mip` field | Source |
|---|---|---|---|
| 3 | MSIE | MSIP | Machine software interrupt |
| 7 | MTIE | MTIP | Machine timer interrupt |
| 11 | MEIE | MEIP | Machine external interrupt |
| 1 | SSIE | SSIP | Supervisor software interrupt |
| 5 | STIE | STIP | Supervisor timer interrupt |
| 9 | SEIE | SEIP | Supervisor external interrupt |

## Enabling Interrupts

```asm
# Enable machine timer interrupt and global M-mode interrupts
li    t0, (1 << 7)     # MTIE bit
csrs  mie, t0          # set MTIE in mie
csrsi mstatus, (1 << 3) # set MIE in mstatus
```

## Interrupt Priority

When multiple interrupts are pending simultaneously RISC-V defines a fixed priority order (highest to lowest) within M-mode:

```
MEI (external) > MSI (software) > MTI (timer)
```

The equivalent S-mode interrupts have lower priority than all M-mode interrupts.

## The Machine Timer Interrupt (MTI)

The timer interrupt is the most commonly used interrupt in bare-metal RISC-V. It is generated by the CLINT when `mtime >= mtimecmp`. The CLINT memory-mapped registers are:

| Register | Address (SiFive FE310) | Width | Description |
|---|---|---|---|
| `mtime` | `0x0200BFF8` | 64-bit | Free-running counter |
| `mtimecmp` | `0x02004000` | 64-bit | Comparison value |

```c
#define CLINT_BASE    0x02000000UL
#define MTIME         (*(volatile uint64_t*)(CLINT_BASE + 0xBFF8))
#define MTIMECMP      (*(volatile uint64_t*)(CLINT_BASE + 0x4000))
#define TICKS_PER_MS  32768UL   // 32.768 kHz reference

void set_timer_ms(uint32_t ms) {
    MTIMECMP = MTIME + (uint64_t)ms * TICKS_PER_MS;
}
```

Clearing the timer interrupt requires **writing a new `mtimecmp` value** greater than the current `mtime`. Setting `mip.MTIP` directly is not writable from software — it is read-only and reflects the hardware comparator.

## The Machine Software Interrupt (MSI)

Software interrupts are used for inter-hart communication (IPIs). The CLINT exposes per-hart `msip` registers:

```c
#define MSIP_BASE   0x02000000UL
// MSIP for hart N is at MSIP_BASE + 4*N
volatile uint32_t* msip = (volatile uint32_t*)(MSIP_BASE + 4 * hart_id);
*msip = 1;   // raise MSI on target hart
*msip = 0;   // clear MSI (done in the receiving hart's handler)
```

## The Machine External Interrupt (MEI)

External interrupts are routed through the PLIC (covered in detail in the next lesson). From the handler's perspective:

1. Enter the interrupt handler (mcause bit 63 set, code = 11).
2. Read the PLIC's **claim register** to get the interrupt ID and acknowledge receipt.
3. Service the device.
4. Write the interrupt ID back to the PLIC's **complete register**.

```c
#define PLIC_BASE       0x0C000000UL
#define PLIC_CLAIM      (*(volatile uint32_t*)(PLIC_BASE + 0x200004))
#define PLIC_COMPLETE   (*(volatile uint32_t*)(PLIC_BASE + 0x200004))

void handle_external_interrupt(void) {
    uint32_t irq = PLIC_CLAIM;      // claim highest-priority pending interrupt
    if (irq == 0) return;           // spurious interrupt
    service_device(irq);
    PLIC_COMPLETE = irq;            // signal completion to PLIC
}
```

## Worked Example: Timer ISR

```c
void __attribute__((interrupt)) machine_timer_handler(void) {
    // Reschedule timer 10 ms from now
    set_timer_ms(10);
    // Perform periodic work
    tick_count++;
}
```

With GCC's `interrupt` attribute the compiler automatically saves and restores all caller-saved registers and emits `mret`. Without it you must handle context save/restore in assembly.

> **Interview answer:** A RISC-V interrupt fires when `mstatus.MIE`, the source's `mie` bit, and the source's `mip` bit are all set. Timer interrupts are cleared by writing a new `mtimecmp`. External interrupts are acknowledged via PLIC claim/complete. Software interrupts are cleared by writing 0 to the CLINT's `msip` register.

## Common Pitfalls

- Reading `mip` to check pending interrupts in a tight poll loop — pending bits for timer and external are set/cleared by hardware, but reading them while `mstatus.MIE = 0` means they never fire.
- Writing to `mip.MTIP` — this bit is read-only; clearing the timer requires updating `mtimecmp`.
- On RV32 platforms `mtime` and `mtimecmp` are 64-bit split across two 32-bit words. Read/write them with a careful double-word sequence to avoid tearing.

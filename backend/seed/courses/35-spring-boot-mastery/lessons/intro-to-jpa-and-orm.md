# Introduction to JPA and ORM

Relational databases store data in tables and rows, while Java works with objects and classes. Bridging that gap manually — writing SQL for every `INSERT`, `SELECT`, `UPDATE`, and `DELETE` — is tedious and error-prone. **Object-Relational Mapping (ORM)** automates that translation, letting you work with plain Java objects while the framework generates and executes the SQL for you.

## What Is ORM?

An ORM maps each Java class to a database table and each field to a column. When you save an object, the ORM converts it into an `INSERT` statement. When you query, it converts rows back into objects. You stay in the Java world; the ORM handles the SQL world.

## What Is JPA?

**Java Persistence API (JPA)** is a *specification* — a set of interfaces and annotations defined in `jakarta.persistence` (formerly `javax.persistence`). JPA does not provide implementations itself; it standardises the API so you can swap providers without changing your application code.

| Concept | Description |
|---|---|
| **JPA** | Specification (interfaces + annotations) |
| **Hibernate** | The most popular JPA provider (implementation) |
| **Spring Data JPA** | Spring abstraction on top of JPA/Hibernate |
| **EntityManager** | JPA's core API for persistence operations |

Spring Boot auto-configures Hibernate as the default JPA provider. You get all three layers out of the box.

## Adding the Dependency

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<!-- a JDBC driver — H2 for development, PostgreSQL for production -->
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

## Your First Entity

An **entity** is a plain Java class annotated with `@Entity`. JPA maps it to a table.

```java
package com.example.demo.entity;

import jakarta.persistence.*;

@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String name;

    @Column(nullable = false)
    private Double price;

    // Constructors
    public Product() {}

    public Product(String name, Double price) {
        this.name = name;
        this.price = price;
    }

    // Getters and setters
    public Long getId() { return id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public Double getPrice() { return price; }
    public void setPrice(Double price) { this.price = price; }
}
```

Key annotations:

- `@Entity` — marks the class as a JPA-managed entity.
- `@Table(name = "products")` — maps it to the `products` table (optional; defaults to the class name).
- `@Id` — designates the primary key field.
- `@GeneratedValue(strategy = GenerationType.IDENTITY)` — delegates key generation to the database (auto-increment).
- `@Column` — customises column constraints such as nullability and length.

## Hibernate DDL Auto

Configure how Hibernate manages the schema via `application.properties`:

```properties
spring.datasource.url=jdbc:h2:mem:testdb
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.hibernate.ddl-auto=create-drop
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

| `ddl-auto` Value | Behaviour |
|---|---|
| `none` | Do nothing (production default for external DBs) |
| `validate` | Validate schema; fail if it does not match |
| `update` | Alter existing tables to match entities |
| `create` | Drop and recreate tables on startup |
| `create-drop` | Like `create`, but drops tables on shutdown |

Use `create-drop` or `create` only in development. Use `validate` or `none` in production and manage schema migrations with **Flyway** or **Liquibase**.

## How the SQL Is Generated

When Spring Boot starts with the entity above and `ddl-auto=create`, Hibernate executes:

```sql
CREATE TABLE products (
    id     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name   VARCHAR(100) NOT NULL,
    price  DOUBLE PRECISION NOT NULL
);
```

You never write that SQL — Hibernate derives it entirely from your annotations.

## Common Mistakes

- **Forgetting the no-arg constructor.** JPA requires a public or protected no-argument constructor to instantiate entities via reflection.
- **Using `ddl-auto=create` in production.** This drops all data on every restart.
- **Not annotating `@Id`.** Without a primary key annotation, JPA throws `AnnotationException` at startup.
- **Mutable static fields.** Fields marked `static` or `transient` are ignored by JPA and will not be persisted.

## Summary

JPA is the standard Java specification for ORM. Hibernate implements it, and Spring Data JPA wraps both to provide repository-level abstractions. Annotate a class with `@Entity` and `@Id`, configure a datasource, and Spring Boot's auto-configuration wires everything together — letting you focus on business logic rather than SQL boilerplate.

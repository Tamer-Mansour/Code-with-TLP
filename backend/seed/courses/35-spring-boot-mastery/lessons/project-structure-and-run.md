# Project Structure and the Run Lifecycle

Every Spring Boot project generated by [start.spring.io](https://start.spring.io) shares a predictable directory layout. Knowing it saves you from hunting for the wrong file at the wrong time.

## Standard Maven Layout

```
my-app/
├── pom.xml                          ← Maven build descriptor
└── src/
    ├── main/
    │   ├── java/
    │   │   └── com/example/myapp/
    │   │       └── MyAppApplication.java   ← entry point
    │   └── resources/
    │       ├── application.properties      ← configuration
    │       ├── static/                     ← served as-is (CSS, JS, images)
    │       └── templates/                  ← Thymeleaf/Mustache views (if used)
    └── test/
        ├── java/
        │   └── com/example/myapp/
        │       └── MyAppApplicationTests.java
        └── resources/
            └── application-test.properties
```

The `src/main/resources` directory is on the classpath at runtime. Anything placed there is reachable via `ClassLoader.getResourceAsStream` or Spring's `ResourceLoader`.

## The Entry Point

```java
package com.example.myapp;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class MyAppApplication {

    public static void main(String[] args) {
        SpringApplication.run(MyAppApplication.class, args);
    }
}
```

`@SpringBootApplication` is a composed annotation that combines three things:

| Annotation | Effect |
|---|---|
| `@SpringBootConfiguration` | Marks the class as a `@Configuration` source |
| `@EnableAutoConfiguration` | Triggers Spring Boot's auto-configuration machinery |
| `@ComponentScan` | Scans the current package and all sub-packages for beans |

This is why placing the entry class at the root of your package tree matters: `@ComponentScan` uses that class's package as the base. Any component deeper in the tree is picked up automatically; anything in a sibling or parent package is not.

## The Run Lifecycle

When you call `SpringApplication.run(...)`, the following happens in order:

1. A `SpringApplication` instance is created and the application type is inferred (servlet, reactive, or none).
2. `ApplicationContext` is created — typically `AnnotationConfigServletWebServerApplicationContext` for a web app.
3. `ApplicationContextInitializer` beans run.
4. The `Environment` is prepared: system properties, environment variables, then `application.properties` / `application.yml` are loaded (in that precedence order).
5. Bean definitions are scanned and registered.
6. Auto-configuration classes are evaluated and conditionally applied (`@ConditionalOnClass`, `@ConditionalOnMissingBean`, etc.).
7. All singleton beans are instantiated and wired.
8. `ApplicationRunner` and `CommandLineRunner` beans execute (useful for startup tasks).
9. The embedded server (Tomcat by default) starts and begins accepting requests.
10. `ApplicationReadyEvent` is published.

## Running the Application

**With Maven wrapper (recommended — no local Maven install required):**

```bash
./mvnw spring-boot:run          # macOS / Linux
mvnw.cmd spring-boot:run        # Windows
```

**Building a fat JAR and running it:**

```bash
./mvnw package -DskipTests
java -jar target/my-app-0.0.1-SNAPSHOT.jar
```

**Passing configuration at runtime:**

```bash
java -jar target/my-app-0.0.1-SNAPSHOT.jar --server.port=9090 --spring.profiles.active=prod
```

Command-line arguments (prefixed `--`) override `application.properties` values.

## application.properties Basics

```properties
# Server
server.port=8080
server.servlet.context-path=/api

# Datasource (example)
spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.datasource.username=postgres
spring.datasource.password=secret

# JPA
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=false
```

Prefer `application.yml` for nested config, but both are equivalent — do not mix them in the same project.

## Common Mistakes

- **Entry class in the wrong package.** If `MyAppApplication` lives in `com.example` but your controllers are in `com.example.web`, they are still found. If you move the entry class to `com.example.myapp.config`, the controllers at `com.example.web` are outside the scan and become invisible to Spring — resulting in 404s with no error.
- **Multiple `main` methods.** Maven packages whichever class `pom.xml` names as `<mainClass>`. Leaving that unset with two `main` methods causes a non-deterministic build.
- **Editing `target/` artefacts.** The `target/` directory is regenerated on every `mvn package`. Always edit source under `src/`, never compiled output.
- **Missing `spring-boot-starter-web`.** Without it, `SpringApplication` detects no servlet environment, starts as a standalone (non-web) application, and exits immediately after the context is ready.

## Summary

A Spring Boot project follows a strict Maven directory contract. The `@SpringBootApplication` entry point bootstraps the entire context from its package downward, and the embedded Tomcat server starts automatically — no external deployment needed.

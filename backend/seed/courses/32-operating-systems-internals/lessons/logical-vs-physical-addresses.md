# Logical vs Physical Addresses

The terms **logical address**, **virtual address**, and **physical address** appear throughout OS textbooks and often cause confusion. This lesson pins down exact meanings and shows how they relate in practice.

## Definitions

### Logical Address
A **logical address** is the address generated by the CPU during instruction execution — the value the program actually uses in load/store instructions. In systems with virtual memory, every logical address is also a virtual address. In simpler systems (early segmentation without paging), a logical address includes a segment selector and an offset, which are combined before hitting the MMU.

> In modern usage, "logical address" and "virtual address" are often used interchangeably. OS textbooks (Silberschatz) formally distinguish them; Linux documentation tends to say "virtual address" for both.

### Virtual Address
The address as seen by the running process. It lives in the process's private address space. Two processes can have the same virtual address pointing to entirely different physical memory.

### Physical Address
The address that appears on the memory bus — the actual location in RAM. Physical addresses are global and unique across the entire machine. Only the OS (and DMA hardware) should ever need to reason about physical addresses directly.

## The Relationship

```
Source Code
    │  (symbolic: variable names, function names)
    ▼
Compiler / Linker
    │  (produces: logical/virtual addresses — e.g. 0x401020)
    ▼
CPU (at runtime)
    │  issues logical/virtual address for every load/store
    ▼
MMU  ← page table loaded from CR3 (set by OS on context switch)
    │  translates: virtual → physical
    ▼
Physical RAM  (e.g., 0x2A3F_0000 on the DRAM bus)
```

## x86 Segmentation: A Third Layer

On x86 (32-bit), addressing involves three values:

1. **Logical address** = segment selector + offset (what the instruction encodes)
2. **Linear address** = base of segment + offset (after segment translation)
3. **Physical address** = after paging (linear → physical via page table)

In 64-bit mode (x86-64), segmentation is largely disabled (all segment bases are 0 for user mode), so logical == linear == virtual. The MMU only performs paging.

```
x86-32                           x86-64 (user mode)
──────────────────               ──────────────────────
logical (seg:off)                logical == virtual
      │                                 │
      ▼  segment descriptor            ▼  (no-op, base=0)
  linear address                   linear == virtual
      │                                 │
      ▼  page table                     ▼  page table
  physical address                  physical address
```

## Why the Distinction Matters

| Scenario | Which address type matters |
|---|---|
| Writing portable C code | Logical/virtual — your pointers are always virtual |
| Implementing a device driver | Physical — DMA engines use physical addresses |
| Debugging a kernel memory bug | Both — kernel virtual ↔ physical mapping (`virt_to_phys` in Linux) |
| Understanding ASLR | Virtual — randomized at process start |
| Optimizing cache performance | Physical — cache sets are indexed by physical address on most modern CPUs |

## Practical Example

```c
#include <stdio.h>
#include <stdint.h>

int global = 99;

int main(void) {
    // This prints the VIRTUAL (logical) address of 'global'
    printf("Virtual address of global: %p\n", (void *)&global);
    // The physical address is invisible to user-space code.
    // Only the OS kernel can call virt_to_phys() or read /proc/self/pagemap.
    return 0;
}
```

To peek at the physical address from user space (Linux):

```bash
# /proc/self/pagemap maps virtual page numbers to physical frame numbers
python3 -c "
import struct, os
addr = id(42)                # some virtual address (CPython object)
page = addr >> 12
with open('/proc/self/pagemap', 'rb') as f:
    f.seek(page * 8)
    entry = struct.unpack('Q', f.read(8))[0]
pfn = entry & ((1 << 55) - 1)
print(f'virtual={hex(addr)} physical={hex(pfn << 12 | (addr & 0xfff))}')
"
```

## Common Pitfall

Using physical addresses in kernel modules with direct pointer arithmetic instead of `ioremap` / `phys_to_virt` — on systems with HIGHMEM or non-identity-mapped regions, not all physical addresses have a kernel virtual address at offset `PAGE_OFFSET`, and dereferencing a raw physical address will access garbage or crash.

**Interview answer:** A logical (virtual) address is what the CPU emits during execution and lives in the process's private address space; a physical address is the actual RAM location on the memory bus; the MMU translates between them using the page table, and user-space code never sees or needs physical addresses directly.

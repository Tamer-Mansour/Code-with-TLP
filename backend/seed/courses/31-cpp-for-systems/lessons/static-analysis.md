# Static Analysis with clang-tidy and cppcheck

Static analysis tools examine source code without executing it, looking for patterns that indicate bugs, undefined behavior, or poor style. Unlike compiler warnings, they perform deeper interprocedural analysis and can catch bugs that only appear in specific call paths.

## clang-tidy

clang-tidy is built on the Clang compiler infrastructure. It has access to the full AST (Abstract Syntax Tree) and type information, making its analysis semantically precise.

### Running clang-tidy

```bash
# Single file
clang-tidy myfile.cpp -- -std=c++17 -I./include

# With a compile_commands.json (generated by CMake)
clang-tidy myfile.cpp        # auto-discovers build flags

# Fix issues automatically
clang-tidy --fix myfile.cpp -- -std=c++17
```

Generate `compile_commands.json` with CMake:

```bash
cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON ..
```

### Check Categories

clang-tidy organizes checks into named modules. Enable them with `-checks=`:

```bash
clang-tidy -checks='bugprone-*,performance-*,modernize-*,readability-*' myfile.cpp --
```

| Module | Finds |
|--------|-------|
| `bugprone-*` | Common bug patterns: integer overflow, suspicious string ops |
| `cert-*` | CERT C++ coding standard violations |
| `clang-analyzer-*` | Deep path-sensitive bugs (null deref, memory errors) |
| `cppcoreguidelines-*` | C++ Core Guidelines violations |
| `modernize-*` | Suggests modern C++ equivalents |
| `performance-*` | Unnecessary copies, inefficient patterns |
| `readability-*` | Naming, braces, simplification |

### Example Output

```cpp
// bad.cpp
void process(std::vector<std::string> items) {  // pass by value
    for (int i = 0; i < items.size(); i++) {    // signed/unsigned comparison
        if (items[i] == NULL) { }               // comparing string to NULL
    }
}
```

```
bad.cpp:1:26: warning: the parameter 'items' is copied for each invocation
    but only used as a const reference; consider making it a const reference
    [performance-unnecessary-value-param]
bad.cpp:2:23: warning: comparison of integers of different signs: 'int' and
    'size_type' (aka 'unsigned long') [clang-diagnostic-sign-compare]
bad.cpp:3:24: warning: comparing basic_string to NULL; can never be true
    [bugprone-string-compare]
```

### Configuration File

Create a `.clang-tidy` in the project root:

```yaml
# .clang-tidy
Checks: >
  bugprone-*,
  cert-*,
  clang-analyzer-*,
  cppcoreguidelines-*,
  -cppcoreguidelines-avoid-magic-numbers,
  modernize-use-nullptr,
  modernize-use-override,
  performance-*

WarningsAsErrors: 'bugprone-*,clang-analyzer-*'

CheckOptions:
  - key: readability-identifier-naming.VariableCase
    value: camelCase
```

## cppcheck

cppcheck is a standalone static analyzer with lower false-positive rates, specialized in finding actual bugs rather than style issues.

```bash
# Install
sudo apt install cppcheck

# Basic usage
cppcheck myfile.cpp

# Enable all checks, specify standard
cppcheck --enable=all --std=c++17 --suppress=missingIncludeSystem ./src/

# Output in XML for CI integration
cppcheck --enable=all --xml 2>report.xml ./src/
```

### What cppcheck Finds

```cpp
// Example: use of freed memory
char* p = malloc(100);
free(p);
strcpy(p, "hello");   // cppcheck: [doubleFree] Memory pointed to by 'p' freed twice
```

```cpp
// Iterator invalidation
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == 42) v.erase(it);  // cppcheck: [eraseDereference] Iterator invalidated
}
```

```cpp
// Integer overflow in condition
unsigned int x = 0;
if (x - 1 > 0) { }   // cppcheck: [unsignedLessThanZero] Unsigned expression is never negative
```

### cppcheck vs clang-tidy

| Aspect | cppcheck | clang-tidy |
|--------|----------|------------|
| False positive rate | Low | Medium (more checks) |
| Requires compilation | No | Yes (needs compile flags) |
| Speed | Fast | Slower (full AST parse) |
| Fixes code automatically | No | Yes (`--fix`) |
| Best for | Quick bug scan | Deep analysis + modernization |

## Integrating into CMake

```cmake
# CMakeLists.txt
find_program(CLANG_TIDY clang-tidy)
if(CLANG_TIDY)
    set(CMAKE_CXX_CLANG_TIDY
        clang-tidy;
        -checks=bugprone-*,clang-analyzer-*;
        -warnings-as-errors=bugprone-*
    )
endif()

find_program(CPPCHECK cppcheck)
if(CPPCHECK)
    set(CMAKE_CXX_CPPCHECK
        cppcheck;
        --enable=all;
        --suppress=missingIncludeSystem;
        --error-exitcode=1
    )
endif()
```

With this setup, CMake runs both analyzers as part of every build.

## Common Pitfall: False Positives

Static analyzers occasionally flag correct code. Suppress specific warnings inline:

```cpp
// clang-tidy suppression
int val = getVal(); // NOLINT(bugprone-narrowing-conversions)

// cppcheck suppression
// cppcheck-suppress nullPointer
process(ptr);
```

Use suppressions sparingly — each one is a place where a real bug might hide.

> **Interview answer:** clang-tidy performs AST-level analysis using full compiler type information, catching bugs and suggesting modernization with optional auto-fix. cppcheck is a lighter standalone tool with low false positives focused on actual bugs. Both should run in CI; cppcheck is fast enough to run on every commit, clang-tidy fits in a nightly or PR check.
